# Clinical Co-Pilot — Test & Eval Results

**Golden gate: 65/65, all five boolean rubric categories at 1.00.** The latest run is
RECORDED in the repo so a grader can open it at HEAD without re-running anything:
- machine record — [`golden/results.snapshot.json`](golden/results.snapshot.json)
- human-readable gate report — [`golden/gate-report.snapshot.md`](golden/gate-report.snapshot.md)

Both are regenerated by `evals/golden/runner.py` + `gate.py` (the live gate reads the
git-ignored `results.json`; these `*.snapshot.*` copies are the committed record, stamped
with the `git_sha` they were run against). See [Latest recorded golden run](#latest-recorded-golden-run).

Two tiers:
- **`copilot/tests/`** — HERMETIC unit tests. No DB, no LLM. Fixtures built in-code.
- **`copilot/evals/`** — DB-INTEGRATION tests against the live local OpenEMR
  MariaDB (the showcase seed). Primary keys are discovered at runtime by
  querying; only stable seed *patient ids* (101/102/23/3) are treated as fixtures.
  The whole eval tier auto-skips (not fails) if the DB is unreachable.

Each test's docstring names the failure mode it guards.

## How to run

From the `copilot/` directory (venv interpreter):

```
.venv/Scripts/python.exe -m pytest tests evals -v
```

- Hermetic units only (no DB needed): `.venv/Scripts/python.exe -m pytest tests -v`
- DB evals only: `.venv/Scripts/python.exe -m pytest evals -v`

The boundary eval sets `COPILOT_MOCK_LLM=true` itself (no Anthropic key / token
spend). All other evals are read-only DB queries.

## T8 — reranker ablation (contribution measured)

The reranker (Cohere rerank-v3.5 / Claude-listwise) was previously pinned to Noop in
eval, so its contribution was never quantified. It now is, over the same labeled set —
[`retrieval/measure_rerank.py`](retrieval/measure_rerank.py),
[`retrieval/rerank_ablation.json`](retrieval/rerank_ablation.json)/`.md`,
sanity-gated in `tests/test_rerank_ablation.py`. Metrics are the reranker-sensitive ones
(recall@1, MRR); recall@5 is first-stage-bound.

| reranker | recall@1 | MRR | vs OFF |
| --- | --- | --- | --- |
| OFF (noop, RRF order) — the keyless shipping default | 0.794 | 0.902 | — |
| ON (lexical, keyless) | 0.647 | 0.760 | −0.142 |
| **LIVE (Cohere rerank-v3.5)** — operator run, key required, 2026-07-21 | 0.735 | 0.858 | −0.044 |
| ORACLE (perfect reranking of the pool — upper bound) | 1.000 | 1.000 | +0.098 |

**The measured finding — honest, and the interesting part:** on this 9-doc, high-signal
guideline corpus the RRF first stage is already near-optimal (MRR 0.902 against a 1.000
ceiling — only **+0.098** of headroom exists), and reranking a pool that small *reduces*
MRR: the keyless lexical method by −0.142, and even live Cohere by −0.044. Reranking earns
its keep on large, noisy candidate pools; here it does not. So **shipping keyless (noop) is
the measured-correct default**, and the reranker stays a swappable stage behind the auto
ladder + this harness — re-run the LIVE row with `COPILOT_RERANK_PROVIDER=auto` + a key on
any future (larger) corpus to re-decide. Measuring it is what let us make that call instead
of assuming a reranker always helps.
